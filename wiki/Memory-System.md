# Memory System Deep Dive

The Memory System (`src/core/memory`) is the cognitive backbone of Mina, allowing the AI to retain facts, relationships, and context across different sessions and conversations.

## 1. Storage Architecture

Data is persisted locally in `data/memory.json`. The structure is designed to be human-readable while supporting efficient programmatic access.

### Data Schema
```json
{
  "USER_ID_SNOWFLAKE": {
    "displayName": "Sam",
    "bio": "Optional manual bio",
    "memories": [
      {
        "text": "Sam likes pizza",
        "category": "preferences",
        "embedding": [0.12, -0.05, ...], // 384-dimensional vector
        "timestamp": 1700000000000
      }
    ]
  }
}
```

*   **displayName**: The name the bot uses to address the user.
*   **memories**: An append-only log of facts.
    *   **embedding**: Generated by `Xenova/all-MiniLM-L6-v2`. This is what allows the semantic search to work.
    *   **category**: Tag used for grouping in the prompt (e.g., `personal`, `plans`, `trivia`).

## 2. Vector Search Engine

Mina uses a local embedding model to perform semantic searches. This means she finds memories based on *meaning*, not just keyword matching.

*   **Model**: `Xenova/all-MiniLM-L6-v2` (Running on ONNX Runtime via `@xenova/transformers`).
*   **Dimensionality**: 384 dimensions.
*   **Algorithm**: Cosine Similarity.

### Retrieval Process
When `getContext(userId, text)` is called:
1.  The user's current speech (`text`) is embedded into a vector.
2.  The system calculates the Cosine Similarity between this query vector and *every* memory vector for that user.
3.  Memories with a similarity score **> 0.25** are considered relevant.
4.  The top 10 results are injected into the System Prompt.

## 3. The Learning Loop

The system does not simply record transcripts. It uses a sophisticated extraction process to distill "facts" from conversations.

### Trigger
The `learnFromInteraction` function is triggered asynchronously after every AI response.

### The Extraction Prompt
The system sends the recent conversation transcript to the LLM with a specialized "Data Extractor" system prompt. This prompt helps the AI to:
1.  **Extract Facts**: Identify new information (e.g., "User mentions they moved to London").
2.  **Duplicate Check**: It performs a semantic similarity check (> 0.80) to avoid storing synonymous facts (e.g., "User lives in London" vs "User's home is London").
3.  **Plan Management**: It detects if a previously stored "Plan" (e.g., "Remind user to sleep") has been completed, and if so, signals the system to remove it.

## 4. Context Injection

During conversation generation, the retrieved memories are organized by category and injected into the prompt:

```text
[User Context]
Name: Sam
[Personal]
- User lives in New York (2 months ago)
[Preferences]
- User likes pizza (1 year ago)
```

### "Truth" vs Claims
The system also performs a background lookup for any *other* users mentioned in the conversation. If User A talks about User B, the system injects User B's verified memories as "BACKGROUND TRUTH" to prevent hallucinations or misinformation.
